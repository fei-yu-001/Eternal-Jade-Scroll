# 用户与云存档数据字典（M6-02-S）

> 实现对照：`GameServer/.../auth/UserEntity.java`、`GameServer/.../save/SaveEntity.java`；
> MySQL DDL：`Database/SQL/V1__user_cloud_save.sql`；关系图：`Database/ER/用户与云存档ER.md`。
> "谁写谁读"中：**注册/登录/上传**指对应 HTTP 端点，**服务端**指 GameServer 业务逻辑。

## 表 users —— 注册用户

| 字段 | 类型（MySQL） | 类型（H2 自动建表） | 约束 | 含义 | 谁写 | 谁读 |
|---|---|---|---|---|---|---|
| id | BIGINT, AUTO_INCREMENT | BIGINT | PK | 用户主键，即 API 回执里的 `userId` | INSERT 时数据库生成 | 登录/me/存档端点、saves.user_id 外键 |
| username | VARCHAR(32) | VARCHAR(32) | NOT NULL, UNIQUE(`uk_users_username`) | 用户名，3–32 字符、不含空白、区分大小写 | 注册时写入，永不再改（本轮无改名端点） | 登录查重、注册查重 |
| password_hash | VARCHAR(100) | VARCHAR(100) | NOT NULL | BCrypt 哈希（自带盐，60 字符）。**明文不落库、不进日志、不进回执** | 注册时写入；本轮无改密端点 | 登录时 BCrypt 比对 |
| token | CHAR(36) | CHAR(36) | NULL, UNIQUE(`uk_users_token`) | 登录令牌 UUID。null=未登录；每次登录换发新值并作废旧值；登出置 null | 注册/登录签发，登出清空 | 所有需授权端点（X-Auth-Token → 查用户） |
| created_at | DATETIME(6) | TIMESTAMP | NOT NULL | 注册时间（服务端本地时区） | 注册时写入 | 暂无消费方（预留审计） |
| token_at | DATETIME(6) | TIMESTAMP | NULL | 最近一次签发令牌的时间，给将来做令牌过期 | 注册/登录时写入，登出清空 | 暂无消费方（预留） |

唯一约束说明：`uk_users_token` 允许多行 NULL（SQL 标准）——所有未登录用户都是 NULL，互不冲突。

## 表 saves —— 云存档

| 字段 | 类型（MySQL） | 类型（H2 自动建表） | 约束 | 含义 | 谁写 | 谁读 |
|---|---|---|---|---|---|---|
| id | BIGINT, AUTO_INCREMENT | BIGINT | PK | 存档记录主键，API 不暴露 | INSERT 时数据库生成 | 服务端内部 |
| user_id | BIGINT | BIGINT | NOT NULL, FK→users(id) | 所属用户 | 上传首次落槽时写入 | 所有存档端点按 (user_id, slot) 定位 |
| slot | TINYINT | TINYINT | NOT NULL, UNIQUE(`uk_saves_user_slot` 与 user_id 组合) | 槽位 1–3，与客户端三档一致 | 上传时写入 | download/list 按槽位取 |
| schema_version | INT | INTEGER | NOT NULL | 上传时客户端声明的存档结构版本。门禁：>10 拒收（40901）；<10 收下并标 migratable | 上传时写入 | 回执与 download 原样带回；服务端不做迁移 |
| payload | LONGTEXT | CLOB | NOT NULL | 客户端存档 JSON 原文（upload 请求体 `save` 字段的原文）。**服务端只存不读**——客户端存档的真相在客户端，服务端不成为第二真相 | 每次上传整包覆盖 | download 时原样返回 |
| updated_at | DATETIME(6) | TIMESTAMP | NOT NULL | 最近一次覆盖上传时间；回执/list 以 ISO8601 字符串输出 | 每次上传刷新 | download/list 返回；将来"云端比本地新"冲突提示的数据源 |

唯一约束说明：`uk_saves_user_slot (user_id, slot)` 是覆盖语义的落点——上传按它
INSERT-or-UPDATE，同一用户同一槽位永远只有一条记录，不存在一槽多版本。

## 边界（本轮明确不做）

- 客户端联网（Unity 端调这些端点）不在 M6-02-S 范围。
- "云端比本地新"冲突比对逻辑未做，list 端点只备好数据。
- 账号找回、改密、多设备并发登录策略、令牌过期均未做（token_at 已预留）。
