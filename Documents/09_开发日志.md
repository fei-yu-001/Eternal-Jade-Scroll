## 2026-09-30（开发 · M6-01 SpringBoot 服务端最小骨架）

> 本条目由领取并行任务包 `17_并行任务包_M6-01服务端骨架.md` 的会话写入。
> `GameServer/` 与 Unity 客户端零文件交集，未碰 `GameClient/` 任何一行。

### 做了什么

1. **工程骨架**：Spring Boot **4.1.1** + JDK 21 + `spring-boot-starter-web`，
   `TwelveJadeServerApplication` 启动类，`application.yml`（端口 18080 走 `TWELVEJADE_PORT`）。
   自带 **Maven Wrapper**（`mvnw` / `mvnw.cmd` + `.mvn/wrapper/maven-wrapper.properties`，
   仅脚本模式不提交 jar），本机无需预装 Maven。
2. **统一返回体 `ApiResponse<T>`（code / message / data）+ `ApiCode`**：
   `0` 成功、`40001` 请求不合法、`40901` 存档版本高于服务端、`50001` 内部错误。
   形状在 M6-01 定死，Unity 端按它写解析代码——现在多写一句注释，胜过联调时改字段名。
3. **`GET /api/health`**：探针刻意不依赖数据库——探针里挂上任何外部依赖，
   "服务活着"和"依赖可用"就混成一个信号，排查反而更难。
4. **存档契约占位**（`/api/save/upload`、`/api/save/download`）：**只做 schema 版本校验，
   不落库**（回执里 `persisted: false` 就是这个意思，免得被误当成云存档已可用）。
   版本高于服务端拒（409 / 40901）；低于服务端收下并标 `migratable`（老客户端会先本地迁移）。
   未存档是**正常状态**：200 / code 0 + `present: false`，不报错。槽位 1–3 与客户端三档一致。
5. **数据库默认不连**：驱动带在 pom 里（runtime 档），连接信息全部走环境变量并隔离到
   `application-mysql.yml`，**仓库里没有账号密码**。要用库时
   `java -jar … --spring.profiles.active=mysql`。
6. **`GameServer/README.md`**：怎么起、端口、接口契约、错误码、数据库启用方式、后续 M6-02/03 边界。
7. **9 个 JUnit 用例**（MockMvc）：探针 2 + 存档契约 7（当前版本收下 / v99 被拒 /
   老版本标待迁移 / 缺 schemaVersion / body 非对象 / 空档位正常 / 槽位越界）。

### 问题与解决

| 问题 | 解决 |
|---|---|
| **Spring Boot 4 换了 JSON 库**：默认 Jackson 3，包名从 `com.fasterxml.jackson` 变成 `tools.jackson`，`JsonNode` 直接编译不过 | 不再用 JSON 库的节点类型接请求体，改用 `Map<String,Object>` + `@ExceptionHandler(HttpMessageNotReadableException)`。契约层只需要"有哪些字段、值多少"，绑死某个库跨大版本还要再踩一次包名 |
| **Spring Boot 4 把 Web 层测试拆成独立模块**：`@WebMvcTest` 挪到 `org.springframework.boot.webmvc.test.autoconfigure`，且 `spring-boot-starter-test` **不再带** `spring-boot-webmvc-test` | 从本地缓存的 jar 里反查真实包名（不靠记忆猜），并显式加 test 档依赖 |
| pom 里 XML 注释写了 `--spring.profiles.active=mysql`，`--` 在 XML 注释里非法，整个 POM 解析失败 | 改写成"激活 mysql profile" |
| 本机没有 Maven 也没有 Gradle | 用任务包预置的方案：Wrapper 随工程提交；本机从 `~/.m2/wrapper/dists` 里已缓存的 Maven 3.9.16 驱动生成 Wrapper，并借本地 124MB 依赖缓存加速 |

### 未完成 / 风险

- **不落库**：这一版没有任何持久化，云存档是 M6-02 的事。回执里 `persisted:false` 就是实话。
- **存档版本常量要跟客户端手工对齐**：`ClientSchema.SUPPORTED_SCHEMA = 10` 对应 Unity 端
  `SaveData.CurrentSchemaVersion`（M5-05 引入的 v10）。**客户端升级存档结构时必须同步改这里**，
  否则老客户端会把新结构的存档塞进来，服务端照单全收却读不懂。已写进 README。
- 任务包原文写的是"v9 结构"，那是制定时的快照；实际按当前 v10 实现，以代码为准。
- 数据库没建表也没连过：M6-02 落库时再定表结构与迁移脚本，现在建表就是没验证过的设计。
- 未做登录注册、冲突处理、AI 网关，也**刻意没引入 Redis / 消息队列**——加了就是还没用上的债。

| 重复劳动：每轮改完要重跑 Unity（3–5 分钟）才发现下一个错 | 这轮改成**先读状态再改**：把 quest 状态/进度打进日志，一次定位"任务还是 Locked、进度 0"，而不是逐个试 |

### 补记十（同日 · 真正的根因：贴图导入被 NPOT 缩放破坏）

连修三轮公式与素材仍不见效后，加了"构建版本戳 + 运行时贴图指纹"自证诊断

公式修正、素材断层修补都是在治标**（公式确实有错、素材确实有缝，但不是用户看到的
那个现象的原因）。74 张美术贴图的 `.meta` 全部改为 `nPOTScale: 0`（None，保留原始
尺寸）后：主角、NPC 货郎、石狮、建筑一次性全部正常——**这个 bug 一直在破坏所有美术
资源，主角的断腿只是最显眼的症状**（货郎此前也只有上半身）。三套验收全绿：

### 补记十一（同日 · 导入守卫：把设置从"改文件"变成"代码强制"）
