## GitHub 备份原则

旧 `feature/front-end` 的未推送历史含两处明文 API 密钥；此外当前四个美术脚本的密钥已改为读 `LUPI_API_KEY`，原值保留在仓库外私有环境文件。没有确认这些旧密钥已经作废，不能把原有历史直接推上 GitHub。

本轮从当前源码、素材和文档创建独立 `backup/verified` 根提交，保留原历史和原暂存区；扫描实际 Git 文件树后才允许上传。排除 Unity Library、临时副本、日志截图、构建产物和本地凭据。此前人物重影、闪身、16 栋建筑地基的已验证修改一并进入备份。

之后在新工作目录正常提交，验证通过便推送 `backup/verified`。不要强推旧分支，也不要 `push --all`。首次快照脚本 `Tools/create-scanned-snapshot.py` 只用于创建全新分支；后续用正常 Git 提交。自动上下文压缩设置保持不变。
