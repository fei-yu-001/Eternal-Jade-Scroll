## A 一句话结论：现在最像荒野的三个数据原因

**一句话**：不是"世界不够大"，而是**天际线只有两层、物件是"撒"的不是"排"的、镇区既无围合也无边界**——三条都是数据分布问题，不是美术问题，纯数据就能先修掉大半。

三条数据原因（全部可复算）：

1. **高度结构塌成两层（中景缺失）**
   `building-plots.json` 99 件里：≥340（2 身位）28 件、≥510（3 身位）9 件、≥800（4 身位）**0 件**；中位高 240（=1.41 身位）。
   九区里 **5 个区一件 ≥510 都没有**（区 1/2/3/8/9，日志 `G-A2` 红 5 项）。广场 1920×1080 视窗只剩 L0/L1 两档（`G-C4`，日志"只有 2 个高度档"）。
   → 2.5D 的纵深靠"前景人—中景屋—背景山"，中景这一层整体缺席，人（170）与屋（中位 240）同框 → 玩具感。出处：日志 `Tools/logs/town-layout.log`、规格 §1.7 硬伤 2。

2. **排布是散点不是街排（"撒"而不是"排"）**
   99 件落在 **88 个不同的 footX** 上（无一条纵向街廓），footY 从 1450 撒到 7780；19 栋 building 的 footX 分布在 2600/3200/3300/…/6100 各 1–3 件（硬证据 6）。
   主街走廊（y 3280–6380、`abs(dx) ≤ half+500`）内只有 **25 件**，横向偏移散布 −683…+716（实测：`dx=-683 lantern-market` 到 `dx=+716 shop-north-street-01`）。
   y 6080–6380 这一段只剩 3 件且全部 <340（`plot-lantern-street-05` 150、`-06` 150、牌坊 6380 落在区间外）→ `G-A6` 唯一红项、`G-B1` 500/286=1.75 偏空旷（宜人 1.0–1.5）。
   → 没有"贴路立面"这个概念，所以既谈不上 D/H，也谈不上街巷收束感。

3. **镇区既拦不住也挡不住（无围合、无边界、无碰撞）**
   `town-map.json` blocked 22004 条全部 y ≤ 3110（mountain 10229 / river 11775），**镇区 y>3110 静态阻挡 = 0 条，walkable = 空数组**（`town-map.json:154754`）。
   再加碰撞半径只有视觉半宽的 **0.34**（`radius/(width/2)` 中位 0.341，且 **99/99 件**满足 `2*radius < width`）→ 玩家能走进贴图约 2/3。
   → 走得出镇、走得进房子，"荒野"与"纸片"两种感觉同时成立。

**关键副结论（必须在 E 节先修的地基）**：`check-town-overlap.py` 现在读的是 `town-map.json.props` 与 `.walkable` ——这两个字段都是空数组（`town-map.json:154754-154755`，`for prop in cfg['props']` 在 `check-town-overlap.py:51`）。所以它的 **PASS 是空输入真值**（"能力存在≠功能存在"同族）。在它修好之前，任何"零重叠"结论都不成立。

## C 建筑排布：沿街成排规则（骨架，够施工）

### C.1 六条成排规则（所有数字由规格 §2.2/§2.5/§2.6 与门禁口径反推）

1. **临街线（setback）**：建筑 `footX = road_x(footY) ± (250 + 220) = ±470`（±40 抖动），即立面贴在**路缘外 220**。理由：`G-A6` 的横向口径是 `half+500`（`check-town-layout.py:305-307`），470 < 750 稳过；同时街墙不压到路面上，`G-A3/A4` 的视窗计数不被虚增。
2. **贴路朝向**：`footX < road_x(y)` 的件朝东（立面朝 +x），`>` 的朝西。**左右对望**：同一 y 段的左右两栋 `abs(dx_L)+abs(dx_R) = 940`，即"门对门 940 宽"（≈ 主街 500 + 两侧各 220），过街视点从任一门槛看对面招牌在 0.94 屏内 → 满足"能看清两侧招牌"（规格 §2.2 主街体感）。
3. **进深/宽度**：`width ∈ [340, 460]`（2.0–2.7 身位宽），矮摊 `width ≤ 260`。宽度上限由 §2.7 的每屏 ≤30 件红线反推（27 件均值已验证安全）。
4. **沿街步距（pitch）**：同侧相邻中心距 **`Δy = 480`**（区间 420–540）。这一条同时打三只鸟：`G-A6` 要求每 700 必有 ≥340 贴路件（480<700 ✓）；`G-A5` 要求视觉事件平均间距 400–600（480 ✓，正好把现状 171 的过密 WARN 销账）；`G-A4` 30 件上限（480 步距下 1080 高视窗同侧最多 3 件 ✓）。
5. **高度档配比（每侧每 5 栋一组）**：`L1×3 : L2×1 : L3×1（仅轴线端点）`，L4 只许出现在区 1/3/4（`check-town-layout.py:52 L4_ALLOWED_ZONES`、`check_c3`）。L3 全镇 ≤6 件（`G-C2`），现状已 3 件（560/620/640/660 中的 620/640/660），**剩余额度 3 件**，只给：戏台（现有 560→抬到 620 已算 L3 则占额）、山门（415→595 占 1）、瓮城门楼（新增，占 1）。**牌坊 660 已是 L3。**
6. **禁区**：牌坊（3960,6380）向南 1200×500 内 0 件 ≥510（`G-D2`）；祠堂–戏台连线 ±250 内无第三件 ≥510（`G-D3`）；广场视窗中心点必须能同框 3 档（`G-C4`）→ 广场边缘固定放 1 件 L2（520–590）与 1 件 L3。

## E 穿模修复（本轮最重要的一节）

### E.0 先修门禁本身：现在的 `check-town-overlap.py` PASS 是假绿

- 它读 `cfg['props']`（`check-town-overlap.py:51`）与 `cfg['walkable']`（`:54`）——两者都是空数组（`town-map.json:154754-154755`）→ **循环体一次都不执行** → 打 `clean` / `RESULT: PASS`（`:71-72`）。
- 它也只判"摆件 × 走廊"，不判"摆件 × 摆件"，也不判"碰撞体 × 贴图本体"（硬证据 2）。

### E.1 碰撞半径公式（取代手填 `radius`）

记 `W = width`（贴图方图边长）、`INSET = 0.72`（立绘本体占方图比例，`check-town-overlap.py:39`），则
**视觉本体半宽 `b = W × INSET / 2 = 0.36 W`**。

```
radius_min(plot) = ceil(0.36 × W_eff)
   W_eff = W                       （普通件）
   W_eff = (W - gateClear) / 2     （blocks:false 的牌坊门洞：只覆盖两侧柱体）
   gateClear = 210                 （门洞净宽，≥1.24 身位，容主角通过）
```

- **判据（新增 G-E1）**：`2 × radius ≥ 0.72 × W`，等价的"贴图可走入侵区" `W×0.72 − 2×radius ≤ 0`。**现状 99/99 违反**（`2r < W` 全中；中位 `radius/(W/2)=0.341`，即入侵区 ≈ 0.32W ≈ 每侧 0.16W）。
- **牌坊例外（`blocks:false`）**：`paifang` W=415 → 门洞 clear 210 → 每柱 `W_eff=102.5` → `radius=37`。写法：`collisionParts: [{dx:-154, r:37}, {dx:+154, r:37}]`，中央 `|dx| ≤ 105` **无碰撞**（门洞可穿，T067 语义保留）。`check-town-overlap.py` 与 `TownMap.CanStand` 必须对 `blocks:false` 走"多柱体"分支，不能退回单个大圆——否则要么穿不过门（单圆锁死），要么门洞两侧也能穿（半径过小）。
- **进深轴不动**：`collisionDepth / height` 现状已 ≈ 0.99（例 `mountain-pine` 248/250、`paifang` 653/660），深度方向没有短板，**只修横向**。统一口径：`collisionDepth = round(0.99 × height)`。
- **逐件批量规则**：`radius = max(现存 radius, ceil(0.36*W_eff))`（只许变大不许变小，避免把已有手感调坏）；`width ≥ 340` 的 19 栋建筑一律按公式重算，`width < 200` 的 D 级小品允许 `radius = ceil(0.30*W)`（细则见下条风险）。

**副作用风险（必须记账）**：半径×2.1 后，密集摆件会互相"卡"出死角，人流走位会变窄。对策：① 沿街 pitch 480 不变，但成排件的 `abs(dx)` 从 470 放到 500，让两侧碰撞圈不咬在一起（500 = 250+250：路缘 250 + 半宽≈110 后仍留 140 通行带）；② 巷（half 100）两侧建筑 `width ≤ 340` → `radius ≤ 123`，巷净通行 = 200 − 0 = 200（建筑在路缘外，不侵入路面）→ 可直接过一人（主角宽 ~60）。

### E.2 新增自动检查：加在 `check-town-overlap.py`（不新开脚本）

理由：它已经是"遮挡/穿模"这道关的唯一落点，且 `run-gates.sh --self-check` 依赖它产出 `RESULT:`（文件内注释自陈"唯一不产出 RESULT 的门禁"已修）。新开脚本会多一道要维护的关，违背"门禁越少越可信"。

新增四条判据（全部用 `building-plots.json` 作数据源，走廊由 `terrainShape` 现算）：
