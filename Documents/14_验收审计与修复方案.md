## P0：交易页货架按钮捕获循环变量

位置：`GameClient/TwelveJade/Assets/Scripts/Presentation/FrontEndTrade.cs:156-165`。

现象：`TradeShelf` 用 `for` 创建按钮，回调写成 `() => PickTrade(list[i].itemId, 1)`。回调真正执行时循环已经结束，`i == list.Count`，点击任一货架行可能抛 `IndexOutOfRangeException`，或者无法选中正确商品。交易页的主要入口因此不可靠。

现有 `FrontEndShot.VerifyTrade` 直接调用 `PickTrade("ganliang", 1)`，没有点击货架按钮，所以当前批处理的 `finished, 0 problem(s)` 不能排除这个问题。

实现方案：

1. 在循环体内先保存 `var itemId = list[i].itemId;`，价格、余量、`MakeRow` 参数和回调全部使用这个局部字符串。
2. 回调不得再次读取 `list[i]` 或其他循环变量。
3. 增加 Play 验收：打开货郎交易页，点击第一行和最后一行，分别断言 `tradePick` 对应商品、结算区名称与行名称一致；至少完成一笔购买。

## P0：交易配置缺失或损坏时的兜底仍会抛异常

位置：`FrontEndTrade.cs:41-60`、`Merchants.cs:90-97`。

现象：`EmptyMerchantTable` 的记忆行是 `"line":""`，而 `MerchantTable.Parse` 明确拒绝空对白。因此 `merchants.json` 缺失或格式错误时，捕获原始异常后再次解析兜底字符串，仍抛 `FormatException`，交易页不能打开。

实现方案：

1. 让兜底记忆行使用非空短句，例如“今日只看货，不谈旧事。”；或允许空记忆表并由 UI 显示 `greeting`。推荐前者，保持配置校验严格。
2. 兜底表仍须包含一个合法商品、一个合法收货类别，且经过 `MerchantTable.Parse` 与 `ItemTable.CrossCheck`。
3. 增加测试：将 `merchants.json` 临时改名或注入坏 JSON，进入交易页应显示兜底货郎，不得抛异常；恢复配置后重新加载正式货架。

## P1：交易页黑市显示价与实际结算价不一致

位置：`FrontEndTrade.cs:162-164`。

现象：无论 `tradeBlack` 是否为真，货架行都显示 `Trade.BuyPrice`；实际 `DoTrade` 在黑市使用 `Trade.BlackPrice`。玩家看到的单价和扣款不一致。

实现方案：显示价使用与结算完全相同的表达式：黑市用 `Trade.BlackPrice(item)`，白日铺用 `Trade.BuyPrice(item, activeSave.localReputation)`。新增断言：黑市铁剑显示 4 成加价后的价格，购买后铜钱减少“显示单价 × 数量”。

## P1：黑市命格 ID 拼写错误

位置：`GameClient/TwelveJade/Assets/Scripts/Core/Trade.cs:58-63`。

现象：正式命格 ID 是 `chiqing`，黑市白名单写成了 `chqing`，导致“痴情种”永远看不到黑市。

实现方案：改为 `chiqing`，并在 `TradeChecks` 增加 `Trade.SeesBlackMarket(NewSave("chiqing")) == true` 与普通命格为 false 的断言。

## P1：地图 NPC 与立绘没有统一排序，且到达回调按错误索引取 NPC

位置：`GameClient/TwelveJade/Assets/Scripts/Presentation/FrontEndMap.cs:68-157, 418-435`。

现象：`ArrangeTownLayers` 只排序 `propOrder`；NPC 虽然被计入玩家目标 sibling index，但 NPC 自身仍保持配置创建顺序，不能按基座 y 正确遮挡。另一个问题是 `PlaceNpc` 找不到贴图时会跳过 `npcOrder`，`pendingNpc` 却仍保存 `town.Npcs` 的原始索引，走到目标后可能从 `npcOrder` 取到另一个 NPC 或越界。

实现方案：

1. 建立统一的深度条目列表，合并有贴图的 prop 与 NPC，按 `baseY` 升序排序；尘点层固定 index 0，之后按排序结果设置所有条目的 sibling index。
2. 玩家插入位置按同一份深度条目计算，不再分别统计两套列表。
3. `pendingNpc` 保存 NPC 的稳定 ID 或 `MapNpc` 引用；到达时直接触发该对象的 ID。不要用可能因缺贴图而压缩过的 `npcOrder` 下标。
4. 增加两个运行时断言：玩家在 NPC 上方和下方经过时 sibling 顺序分别正确；配置一个缺失贴图的 NPC 时，点击其他 NPC 仍能搭话且不抛异常。

## P1：交易批量购买的“部分可买”被 UI 预检查挡住

位置：`FrontEndTrade.cs:271-283`。

现象：点击“多买一打”时，UI 先要求玩家拥有整批金额；即使钱足够买其中一部分，也会整批拒绝。Core 的 `MerchantLedger.Buy` 本身支持按实际钱数和库存返回部分成交，表现层没有利用这个结果。

实现方案：去掉“必须付清整批”的硬拦截，直接调用 Core；或先将请求量裁剪到 `coins / unit` 与货架余量，再调用 Core。成交后按 `moved` 显示实际件数和实际总价。验收：铜钱只够买 2 件、点击买 12 件时，应成交 2 件，剩余货架与铜钱准确。

## P1：商人配置允许重复货架行，退货会重复加库存

位置：`Merchants.cs:77-83`、`Trade.cs:156-160`。

现象：同一 item ID 在同一货架或两个货架重复出现时，`TakeFrom` 会逐行扣货，但 `GiveBack` 对所有匹配行都加回完整退货数量，可能凭空增加库存；UI 也会出现重复行。

实现方案：解析时建立 `HashSet<string>`，拒绝 stock 内重复、hidden 内重复以及 stock/hidden 交叉重复。另加配置测试覆盖三种重复情况。作为防御，`GiveBack` 只回填一条明确来源的库存行，不能对所有匹配行循环加回。

## P2：物品堆叠上限只校验全局 99，没有校验配置中的单品上限

位置：`Inventory.cs:35-45, 157-167`、`SaveRepository.cs:77-80`。

现象：正式表中干粮上限 9、柴刀上限 1，但存档校验只要求每格不超过 99。外部写入 `ganliang:99` 会被当成合法存档；迁移也只按全局 99 截断。

实现方案：在不让 Core 直接依赖 Unity Resources 的前提下，为 `InventoryRules.IsValid`/`Normalize` 增加可选 `ItemTable` 参数；已知物品按 `ItemDef.Stack` 校验和截断，未知物品按全局上限保留以支持旧内容恢复。由 Unity 启动时加载正式表并注入 `SaveRepository`，或在存档写入前调用带表版本。补充干粮 10、柴刀 2 的拒绝测试，以及迁移截断测试。若本阶段暂不改存档接口，必须在技术债务中明确“99 是存档层上限，不是道具层上限”，不能宣称单品堆叠已验收。

1. `dotnet run --project Tools/SaveChecks/SaveChecks.csproj` 全部通过，且包含黑市 `chiqing`、重复货架、批量部分购买和物品单品上限测试。

3. Unity Play 批处理重新生成菜单、问命、城镇、行囊、交易页截图；日志最后必须是 `finished, 0 problem(s)`。
4. 人工点击交易页货架首行/末行、黑市页、批量购买、卖出确认、Esc 返回城镇；人工移动到 NPC 前后检查遮挡和搭话对象。
5. 验收结束后删除临时存档，不终止机器上其他 Unity 进程，并记录本次日志路径。

## 验收工具本身的补强

`FrontEndShot.VerifyTrade` 需要通过实际 UI 层找到货架行的 `Button` 并调用 `onClick.Invoke()`，至少覆盖首行与末行；不能只调用控制器公开的 `PickTrade`。同时把交易页运行期 `LogType.Exception` 作为失败，保留异常的堆栈和页面步骤，避免“截图完成”掩盖交互异常。
