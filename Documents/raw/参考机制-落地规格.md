## 二、#1 零引用棘轮守卫

- **参考项目原做法（只述）**：`my_ai_town` 有一个独立守卫脚本，扫全仓找出"定义了但别处零引用"的
  公开类型与资源路径；存量一次性进 baseline 文件、**只减不增**；新增项必须同时进 whitelist 并逐项
  写明 `purpose / consumer / owner`，三者缺一即红。要点是**"存量冻结 + 增量卡口"两件事分开**，
  否则存量一多就没人愿意开这个关。
- **本仓落点（建议）**：新增 `Tools/checks/zero_reference_scan.py`
  + `Tools/checks/zero_reference_baseline.json` + `Tools/checks/zero_reference_whitelist.json`。
  扫描面：`Assets/Scripts/**` 的 `public` 类型名，与 `Resources/Config/*.json` 的顶层 id。
- **输入 / 输出**：输入=两个 json + 源码与配置目录；输出=候选清单，stdout 打印，退出码 0/1。
- **判据**：
  1. 候选总数 **不大于** baseline 中的记录数（只减不增）；
  2. 任何不在 baseline 也不在 whitelist 的候选 → 退出码非 0；
  3. whitelist 里缺 `purpose/consumer/owner` 任一键 → 退出码非 0；
  4. **自检**：故意在临时副本里加一个孤儿类型，断言它变红且退出码非 0（G-1 第 4 条要求）。
- **预计工时**：1.0–1.5 h（扫描器本体 45 min，baseline 首次生成与人工过一遍 30 min）。
- **与谁的文件冲突**：**`Tools/**` 是夜1 的白名单（G-3 夜1 任务书）**。本条规格落在夜1 域内，
  夜3 不执行 —— 按 G-1 第 6 条停止条件，**停在这里交统筹席 B 派单**。

## 三、#3 套件不许缩水（required_tests 钉数）

- **参考项目原做法（只述）**：一个守卫脚本钉住"每个测试套件至少 N 条断言"这个下限，
  并把 N 写在一个显眼的位置。它治的不是"测试不够多"，是**"套件悄悄缩水"**——
  有人加了一个 `if` 让某段不跑，总数掉下来但依旧全绿。
- **本仓落点（建议）**：新增 `Tools/checks/required_tests_check.py`（或并入 SaveChecks 的一个
  `Check` 计数断言）；钉数表单独一个 json 或直接写进脚本头部常量。
  需要钉住的六关 + 四支 Unity 夹具，逐项一个下限。
- **输入 / 输出**：输入=各夹具日志 / 断言计数；输出=每项实际数与下限对照表；退出码 0/1。
- **判据**：
  1. 任一夹具实际断言数 **低于** 其下限 → 退出码非 0；
  2. 下限只能调高、不能调低（调低要在同文件留一行日期与理由）；
  3. **自检**：故意把某夹具下限临时抬高 1，断言它变红且退出码非 0。
- **预计工时**：1.0 h（脚本 30 min + 跑六关取当前实际数填表 30 min）。
- **与谁的文件冲突**：同 #1，**落在夜1 的 `Tools/**` 白名单内**，夜3 不执行，交 B 派单。
  另注：本条要读 Unity 夹具日志，而 Unity 夹具**本机未安装 Unity 跑不了**——
  下限只能先按"申报数"填，并标注"未实测"，等有 Unity 的机器补齐。

## 四、#4 加载期拒绝而非降级

- **参考项目原做法（只述）**：资源 catalog 在**加载期**做一次集中校验——schema 版本、几何、
  键集（**数量与成员都比**）、路径穿越、引用资源是否存在，任一条不符就 `push_error`
  并且**不给贴图**。要点是"宁可这一步红，也不要运行期静默给个降级物"。
- **本仓三处待翻向**（架构文档 §11#4 已点名）：
  | 编号 | 现状 | 证据 |
  |---|---|---|
  | T098 | `ItemFlags.Current` 默认空表（查不到标记就当"什么都不门控"） | `Economy/ItemFlags.cs`：`Current { get; set; } = Empty` |
  | T099 | `TierRank` 找不到品阶返回 `-1`，调用方照常排序 | `Economy/BagService.cs`：`TierRank(...)` 末尾 `return -1` |
  | T058 | `radius` 靠 24px 兜底 | `Core/TownMap.cs` 解析处 |
- **本仓落点**：`Assets/Scripts/Economy/ItemFlags.cs`、`Assets/Scripts/Economy/BagService.cs`、
  `Assets/Scripts/Core/TownMap.cs`。
- **输入 / 输出**：输入=配置表与物品表；输出=解析期 `FormatException`（本仓既有约定：
  **配置表解析失败必须抛 FormatException**），而不是返回默认值。
- **判据**（逐条）：
  1. `ItemFlags` 加载后若表里存在 `fateGated` 项但 `Current` 为空 → 抛；
  2. `TierRank` 遇到未登记品阶 → 抛，不再返回 `-1`；
  3. 缺 `radius` 的配置项 → 抛，不再 24px 兜底；
  4. 每条都要有**故意改坏一条配置、断言它变红**的自检。
- **预计工时**：1.5 h（三条各 0.5 h，含自检）。
- **与谁的文件冲突**：`Assets/**` 是 G-1 第 3 条明令夜3 不碰的域；
  且 `Economy/` 与 `Core/TownMap.cs` 涉及员工线既有产物。夜3 不执行，交 B 派单。
- **自我披露**：T099 这条我在上一轮（以员工 L 身份）**亲手撞过并记进过日志**——
  `TierRank` 当时还把权重写成了"序号取反"，导致理包顺序整个颠倒，是被断言抓住才改正的。
  换句话说：#4 这个病在本仓**不是理论风险，是已经发生过一次的真实故障**。

## 五、#6 只画 3 向 + 左向运行时镜像

- **运行时镜像：已落地，建议不再单独立项。**
  取证：`PuppetActor.cs:234-241 ApplyMirror()`（对 LegL/LegR/Torso/Head 四片做 UV 镜像）、
  `:295 SetMirror(bool)`、`:300-301` 转向时给 80ms 挤压过渡而非硬切。
- **"只画 3 向"：建议不落地 + 理由**（按 G-5 停止条件，找不到落点不许硬凑）。
  理由：参考项目那条是为**预烘焙多向图集**服务的（控制美术量：只画 3 向，第 4 向运行时镜像）。
  本仓纸偶走的是**分层切片 + UV 运行时镜像**（`Tools/split-puppet-layers.py`），
  根本没有"多向图集"这个对象，"只画 3 向"因此**没有落点**。
  若要保留这条的意图（控美术量），建议改成对等的本地约束：
  **"纸偶切片层数上限 N 层 + 新增切片必须登记用途"**，落点 `Tools/split-puppet-layers.py`（夜1 域）。
- **与谁的文件冲突**：`Tools/**`（夜1）；若改切片约束则同时涉及美术资产（P 线）。
