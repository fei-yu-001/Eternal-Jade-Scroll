## 0. 反推方法与置信度口径（先摆清楚，免得被读成"我替他们定了基线"）

**命令（每一行都可逐条复跑）**：

```bash
git log -1 --format='%h|%ad|%s' --date=format:'%Y-%m-%d %H:%M:%S' --before="<报告 mtime>"
git cat-file -t <sha>                       # 过滤掉不是 commit 的十六进制噪声
git merge-base --is-ancestor <sha> HEAD     # 声明的 sha 是否 HEAD 可达
Get-Item <报告> | Select-Object LastWriteTime
```

**置信度三档（我按这个口径判，判错是我的口径错，请你改口径不要改我的行）**：

| 档 | 判据 |
|---|---|
| **唯一** | 反推 sha **出现在报告正文自己声明的 sha 集合里** ⇒ 有自证交叉，可唯一回填 |
| **不唯一** | 正文声明了 sha，但**不含**反推值 ⇒ 声明的是别的东西（开工基线 / 副本基线 / 他人提交 / 被核报告的 sha），**无法唯一确定"当时 HEAD"** |
| **不可得** | 正文**没有任何 commit sha 声明** ⇒ 反推值仅由 mtime 得来，**无交叉证据**，只能叫"最接近的 HEAD" |

**一条必须先说的方法局限**（B 席 :10054 已点破，我这轮实测坐实了它）：
`--before=<mtime>` 反推出来的是**"最后一次改这个文件时"的 HEAD**，不是**"证据来自那棵树"的 HEAD**。
若一份报告被二次编辑过（比如我自己那份索引 01:01 追加了第二轮），反推值就漂到第二次编辑的时刻去了。
⇒ **"唯一"只表示两件事对上了，不表示它等于证据树。**
