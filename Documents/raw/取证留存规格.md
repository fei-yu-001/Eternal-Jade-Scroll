## 1. 批次坐标（R1）

**规定**：任何一次出图 / 出日志 / 出报告，产物里必须自带**批次坐标**三件套：

```
批次: <YYYY-MM-DD HH:MM:SS> / HEAD=<短sha> / 工作树=<clean|dirty: 文件1,文件2…>
```

- 报告：写在**标题下方第一行**（机器可解析，不许只写在正文里）；
- 日志：由跑批脚本在首行注入（不是事后手写）；
- 图：写不进 PNG 就写进**同目录同名的 `.batch.txt`**，或者落进带批次后缀的目录（见 R3）。

**防住今晚的**：`索引-取证与报告.md` §2.2 那次 **md5 0/20 全不符**。三份报告 mtime 是 10-05 19:43 / 21:03 / 21:29，
盘上 `Tools/screenshots/k-combat-01…09.png` mtime 是 10-06 00:28:55~57 —— **报告比图早 3~5 小时**。
因为谁都没写批次，这件事只能靠"mtime 推理"才能分辨是"批不同"还是"取证假"，
按 B 席判据③判成了"跨批不可比"，但**推理链脆弱**：换个人就可能判成假取证。
更硬的证据是我 00:20 与 00:35 两次读同一张图，字节数自己变了（`k-combat-01` 469031 → 470077），
**15 分钟内被复跑覆盖了一次**——有批次坐标的话，这一眼可见，不用推理。

## 2. 活日志与证据日志分名（R2）

**规定**（沿用员工 M 既有做法，**不新增发明**）：

| 用途 | 命名 | 可否被下一次跑覆盖 |
|---|---|---|
| 活日志（盯进度用） | `m-live-<夹具>.log` | **可以** |
| 证据日志（写进报告的判据） | `m-<说明>-<短sha>-<YYYYmmdd-HHMM>.log` | **不可以** |

报告里引用的**只能是证据日志**，并写全名。

**防住今晚的**：`m-world-wire-report.md:281` 声明 `[TerrainPropShot] suite finished, 7 problem(s)`。
我第一版核对脚本按"盘上最后一条判据"取值，拿到 `terrain-props.log:1877` 的 `0 problem(s)`，
直接判成 **MISMATCH**——**是我错了，不是报告错了**：改成逐字搜声明原文后，`o-regress.log:91` 一次命中
`[TerrainPropShot] suite finished, 7 problem(s)   （同一次运行内 "62 项断言通过"）`。
**同一个夹具在盘上有 7 份以上不同批次的判据行，按"最新一条"核必然误判。**

## 3. 取证图禁止就地覆盖（R3）

**规定**：出图落到 `Tools/screenshots/<线>-<说明>-<短sha>/` 这样的**批次目录**下；
**禁止**把新图写回 `Tools/screenshots/k-combat-01-bodylock.png` 这类**无批次后缀的裸名**。
确需固定裸名（比对类用例）时，先 `cp` 一份到批次目录，裸名只允许作为"当前最新"的软引用。

**防住今晚的**：同一条（R1 里那条）——`k-combat-01/06/09` 三张图在我核验的 15 分钟内字节数变了。
它是 0/20 不符的根因，也是"任何以 md5 为判据的核验都不成立"的根因。

## 4. 报告引用日志必须给「文件名:行号」（R4）

**规定**：报告里每一条判据必须写成 `文件名:行号 → 原文` 三件套；
**不许**只写判据值（"`0 problem(s)`"），也不许让核验者自己去"找最新一条"。

**防住今晚的**：同上 R2 那次——`m-world-wire:281` 若写成 `o-regress.log:91 → [TerrainPropShot] suite finished, 7 problem(s)`，
我第一次就命中，不会先误判一次 MISMATCH 再回头改脚本。**误判一次的成本是我多花了两个来回**，
而误判发生在"报红"方向上，若被当结论发出去就是一次冤案。

## 6. md5 表必须带批次坐标（R6）

**规定**：报告里每一张取证图的 md5 行必须同时给出**出图批次**（时间 + 基线 sha）；
**没有批次的 md5 一律标注"不可核"**，不算通过也不算不符。

**防住今晚的**：`n2-tempo-report.md:146-154`（9 个）、`n-combat-feel-report.md:160-167`（8 个）、
`o-life-loop-report.md:211-213`（3 个）三张 md5 表，共 20 个值，**与盘上产物 0/20 相符**，
且同一张图在两份报告里值还不同（`k-combat-01`：`82e18cf6` vs `ec88a56e`）。
若表里有批次，这 20 行当场可判；没有，就只能靠 mtime 推理（见 R1）。

**规定**：报告落盘的条件是**它引用的证据（日志/图）已经以证据命名落盘**；
只落报告、不落证据，或只落证据、不落报告，都算**半截**，不许申报完成。
