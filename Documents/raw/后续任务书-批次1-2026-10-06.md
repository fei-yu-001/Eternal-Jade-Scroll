## §0 通用规则（每份任务书都适用，不再重复）

1. **先只读盘点，后动手**。开工第一件事是把"将要改的文件 + 它们的当前内容/行数/md5"列出来贴进报告。
   不许凭记忆说"我知道那个文件"。
2. **只改白名单里的文件**。需要改白名单外的任何文件 → **停止并报告**，不许顺手改。
3. **git 只允许只读命令**（`status` / `log` / `diff` / `show` / `rev-parse`）。
   **禁止** `git add` / `git commit` / `git push` / `git stash` / `git checkout --` / `git reset`。
   本批所有任务都**不提交**，由人复核后统一提交。
4. **脚本改文档后必须回读验证**。`grep -c "<唯一标题>" <文件>` 命中数对不上就是没写进去。
   **脚本 `rc=0` 不是"改动已落地"的证据**（历史事故：python 插入锚点写错、静默没插进去）。
5. **不许新建目录**（T-01 的 bundle 目录除外，且必须在仓库外）。
6. **不许"为了不清而加预留"**：删东西要写"为什么删"，不许写"以后可能要用"。
7. **不确定 → 停手写报告**。报告里写明"我卡在哪、我试过什么、我需要谁裁决"。**猜着做是最坏的结果**。
8. **每条结论都要能复算**：给出命令原文 + 输出原文 + 退出码。**"我看过了"不算证据**。
9. 报告统一写进 `Tools/logs/<gate 代号小写>-report.md`（`Tools/logs/` 是已跟踪目录，放进这里才入册）。

## T-04 ｜ 验证树根治：用 `git worktree` 导出 HEAD，不再复制文件

**Gate 代号**：`VERIFY-TREE`（本任务**只写新脚本**，不接线）

**一句话目标**：写一个 `Tools/verify-tree.sh`，把"副本来历"从"脚本约定"变成"机器事实"：
导出纯 HEAD + 显式 overlay + 逐件 md5，自证四记篡改都能被拦住。

**为什么做**：T114（rubocopy 目录条目搬 0 个文件）、Q1.7/T065（跑绿的树不是 HEAD）说明
"用复制构造被测树"是结构性薄弱点。D-53 的 sha+清单自证是止血，本任务是根治。

**上岗先读（只读）**
```bash
sed -n '1,120p' Tools/batch-verify-M.sh
grep -n "robocopy\|cp -r\|rsync\|md5\|sha" Tools/batch-verify-M.sh
```

**白名单**
- 新增 `Tools/verify-tree.sh`
- 新增 `Tools/logs/verify-tree-report.md`
- 夹具只准落 `.batch/night1/` 或 `.batch/verify-tree/`（**`.batch/` 不入 git**）

**禁止**
- **不许修改** `batch-verify-M.sh` / `-N.sh` / `-O.sh`（接线是下一个任务）
- 不许改任何被测脚本、门禁、配置
- 不许在仓库内新建目录（除 `.batch/*`）

**步骤**
1. 设计并写 `Tools/verify-tree.sh`，支持：
   - `bash Tools/verify-tree.sh export <目标目录>`：用
     `git worktree add --detach <目标目录> HEAD`（或 `git archive HEAD | tar -x -C <目标目录>`）
     导出一棵**纯 HEAD** 树，并打印 `git rev-parse HEAD` 的 sha。
   - `bash Tools/verify-tree.sh overlay <目标目录> <清单文件>`：按清单**逐件**从工作树覆盖到目标树，
     覆盖前后各算一次 md5，打印 `路径 / 工作树 md5 / 覆盖前 / 覆盖后`。
     - `overlay_guard`：清单里每条路径必须能对上"本线 OWNED 写域"，对不上 → **中止**（rc 非零）。
   - `bash Tools/verify-tree.sh check <目标目录> <清单文件>`：复算 md5，确认"目标树 = HEAD + 声明的覆盖"，
     多一件或少一件都中止（rc 非零）。
2. 写自证（**四记，每记都要 rc 非零，且点名是哪一件**），夹具落 `.batch/verify-tree/`：
   - ① 清单里少搬一件（文件在目标树里缺失）
   - ② 目标树里混进一件不在清单里的别人的文件
   - ③ 删掉一份 `.png.meta`
   - ④ 树身份 sha 与当前 HEAD 不一致（先 export 再切 HEAD）
   再跑一记"完好情形"必须 rc=0。
3. 把 5 次运行的**命令 + 输出原文 + 退出码**贴进报告。
4. 报告末尾写"如何接入 `batch-verify-*.sh`"的三步方案（**只写方案，不实施**）。

**验收**
- 5 次自证输出齐全，4 记篡改全被拦（rc 非零且点名），完好情形 rc=0
- `verify-tree.sh` 里**没有** `robocopy`
- 覆盖清单的每件都有 mtime + md5 留痕（D-53 判归属看 mtime）

**停止条件**
- 若 `git worktree` 在本机不可用 → 改用 `git archive`，并在报告里说明；两者都不可用 → **停手**
- 若发现需要改 `.gitignore` 才能让目标树干净 → **停手报告**（不许改 `.gitignore`）
- 若 overlay 清单与现有 `batch-verify-*.sh` 的 MINE 格式无法对齐 → 先报告格式差异，不许自己重定义

**回滚**：删掉新增脚本与 `.batch/verify-tree/`；`git worktree prune`（若用了 worktree）。
