# 项目架构与冗余代码审查（2026-11-20）

本次依据当前 `backup/verified` 工作树、程序集定义、代码调用、Unity 资产 GUID 引用及实际编译/测试结果。
原 Unity 工程和自动上下文压缩设置保持原状；服务端仅整理等价实现和文档，本次不涉及线上部署。

## 当前架构

```text
Unity FrontEnd 场景
  └─ Presentation：页面、地图、人物、战斗画面与输入
       ├─ Core：存档、任务、对白、地图数据与章节
       ├─ Combat：战斗规则与世界战斗会话 → Core
       └─ Economy：行囊、制作、物价与气运 → Core
Network：HTTP、认证与云存档 → Core + Presentation（仅为 JSON 适配器）
UI/Auth：登录和云存档面板 → Network + Presentation + Core
Editor：Unity 验收夹具，共用的纯 C# 经济验收套件
Tools/SaveChecks：独立控制台验收，显式链接相同套件源码

Java 服务端：Controller → 用户服务/JPA Repository → MySQL
  ├─ 认证、会话令牌、登录限流
  ├─ 云存档上传/读取、版本与槽位契约
  └─ 健康接口、统一响应/错误处理、只读运维导出工具
```

清理后客户端运行源码 217 个文件、34,324 行：Core 31 / Combat 12 / Economy 9 /
Presentation 151 / Network 9 / UI/Auth 5。六个运行程序集没有依赖环。
服务端主源码 19 个 Java 文件、1,422 行，仍是账户与云存档服务，不承担实时多人战斗。

## 已完成的清理

### 1. 验收代码退出运行时程序集

原 `Assets/Scripts/Economy/InventoryEconomySuite.cs` 为 2,640 行测试，只有编辑器
`InventoryEconomyShot` 与控制台 `InventoryEconomyChecks` 调用。现在连同 `.meta` 移至
`Assets/Editor/InventoryEconomySuite.cs`，保留 GUID 与类命名空间。
`SaveChecks.csproj` 显式链接该文件；两条测试路径仍共用一份实现。

原放置方式使测试源码属于运行程序集；是否被最终包裁剪取决于构建设置，本报告不声称已经测出包体节省值。
本次已用去掉 `UNITY_EDITOR` 和 Editor 源码的独立编译验证，输出程序集没有该测试类。

### 2. 删除 7 个无引用的旧视觉类

删除以下脚本及其 `.meta`：

- `AtlasFogGraphic`：旧地图雾层。
- `MemoScrollHangerGraphic`：旧卷轴悬挂装饰。
- `MeridianFlowGraphic`：旧经脉流动效果。
- `WarmSanctumGraphic`：旧修炼暖雾效果。
- `GuofengHudTrim` 与同文件 `GuofengHudFeedback`：旧 HUD 几何饰件和交互效果。

从仍在使用的 `GuofengHudArt.cs` 中移除独立的 `JadeLotusMotion` 类，保留
`GuofengHudArt` 与 `GuofengHudRefresh`。

依据：全项目 C# 调用与配置检索无消费者，Unity 场景/预制体/资源无对应 GUID 引用，
运行代码未发现按名称装载这些类型的反射入口；清理后编辑器和玩家源码编译通过。
没有按“类名出现次数少”删除扩展方法类，也未删除旧存档兼容路径。

### 3. 修复测试依赖被当作日志排除的问题

经济测试要求读取 `Tools/logs/o-karma-ledger.md`，但整个日志目录被 Git 忽略，干净检出缺文件。
改用受版本管理的 `Documents/气运事件接线表.md`，保留 25 条事件及 2 条已接线的事实核对。
移除前独立测试为 563 通过 / 3 失败；改后同一核心套件为 566 通过 / 0 失败。

`SaveChecks` 增加显式 `--suite economy|chapters`，便于独立验证；无参数仍执行原完整检查，
未知参数报错，选择子套件时输出明确说明未运行全量。

### 4. 清理章节测试的无效状态

删除 `walked`、`walkedError` 和 `lastWalkError` 等只赋值未消费的状态，
改为把失败章节和原因返回给已有断言。章节完整推进、幂等与门控 22 项通过，编译警告消除。

### 5. pi 独立服务端审查及复核

pi 阅读了服务端源码、配置、契约和测试后给出 4 项问题，主审逐项确认并处理：

- `SaveController.upload` 已生成 `payload` 用于大小校验，保存和并发重试又分别序列化相同对象。
  两处改为复用同一个 `payload`，保持 UTF-8 大小限制、null 保留、重试逻辑和接口语义不变。
- `API.md` 宣称未知异常均返回 `500/50001`，实际 `GlobalExceptionAdvice` 仅处理体积超限，
  `ApiCode.INTERNAL_ERROR` 明确为预留。文档已改成实际行为，不凭空补新响应协议。
- `UserEntity.tokenAt` 的“将来做过期”注释已修正；过期判定实际集中在 `AuthTokens`。
- 删除 `GlobalExceptionAdvice` 中两条同包冗余 import。

pi 未发现更多可确认的废弃服务端业务实现；存档导出工具、令牌工具、版本常量和旧存档兼容逻辑保留。
pi 默认通道首次返回 403，随后使用本机已有的备用通道完成审查；期间有一次上游流错误。
此次未修改 pi 的全局配置或自动压缩设置。原始审查结果仅留本地日志目录。
