# AI 协作规则（2026-09-27 更新）

> 用户在备考的一年多里以玩家身份参与，负责试玩、提供想法和审核关键剧情。AI 负责项目的日常实现、测试、记录和整理。2026-09-03 版「核心代码均由本人编写」的要求已被用户的新授权取代；以后对外介绍应如实标注 AI 参与的范围。

## 分工

- 用户：给出体验反馈、世界观与剧情想法；审核章节梗概、关键人物动机、重大分支和结局。
- AI：维护客户端工程、素材来源、存档兼容、测试、日志、技术债务与 Git 提交；在重要设计转折处提出可试玩或可审阅的方案。
- 不无人值守开发。用户发起开发会话后，从仓库当前状态和日志接续工作。

## 每周期流程

1. 检查当前代码、提交状态、开发日志和上周期遗留问题。
2. 选一个玩家可感知、可以验收的小目标并实现。
3. 运行该目标需要的编译、自动检查与手工体验检查；如受外部条件阻断，写明没有执行的部分。
4. 更新开发日志、技术债务和下一周期目标，提交可恢复的代码状态；网络通畅时同步 GitHub。

## 质量与透明度

- 主线开发按阶段推进，`main` 应保持可打开和可运行。未经验证的功能不标记为完成。
- 配置和静态内容尽量数据化；新资产记录原始来源、加工过程、许可或服务条款。
- API 密钥保存在本机环境中，不提交到仓库、日志或游戏构建。
- 试玩反馈以玩家能看到和能操作的结果描述；技术细节在开发日志解释，方便用户将来接手学习。
- 完整 Windows 试玩包在可玩里程碑制作；普通周期以编辑器运行和截图、录屏验收。
